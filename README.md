# AF5640-gorup

**DistributionCheck 收益分配核对平台**。面向 AF5640 小组项目，核对一次代币收益分配中的应付、已确认实付、待确认及差异，并导出可追溯记录。

项目名称按要求保留为 **AF5640-gorup**。界面支持简体中文与 English，前端 React + TypeScript + Vite，后端 Python + FastAPI，金额使用 Decimal。第一版无数据库，当前批次仅保存在浏览器页面会话中；后端按请求独立处理，刷新后重新上传。

## 启动

首次获取源码：

```bash
git clone https://github.com/iamwzzr/AF5640-gorup.git
cd AF5640-gorup
```

当前电脑已配置依赖并构建完成后，在项目目录运行：

```bash
./start.sh
```

打开 **http://127.0.0.1:8000**。Mac 也可双击 `start.command` 启动，在终端按 Ctrl+C 停止。

换电脑或重新安装时，需要 Python 3.12（支持 3.10+）及 Node.js 22.12+ 或 24 LTS，然后执行：

```bash
./setup.sh
./start.sh
```

可通过 `AF5640_PYTHON=/完整路径/python3 ./setup.sh` 指定 Python。依赖锁定于 `frontend/package-lock.json` 和 `backend/requirements.lock.txt`。安装虚拟环境不能跨电脑复制，应在目标电脑重新创建。当前端口被占用时可运行 `AF5640_PORT=8001 ./start.sh`。

开发时运行 `./dev.sh`，前端在5173端口，后端在8000端口，前端通过代理请求后端。修改前端后，用 `npm --prefix frontend run build` 更新正式界面。

## 使用流程

网站先打开产品介绍；点击顶部“收益核对”，或介绍页中的“打开核对工具”进入以下流程。“试用示例 / 收起示例”位于核对工具的步骤区域。

1. **填写规则**：填写项目、这次发放的编号、按哪天的持有数量计算、每个代币发多少、最晚哪天发完和检查到什么时候。其他信息收在“更多设置”中。
2. **上传表格**：上传收款名单和付款记录，点击“检查表格”。通过后才能开始核对；没有现成表格可以先下载模板，用 Excel 填写并保存为 CSV。
3. **查看结果**：先看“这次该发多少、表格里已发多少、还有多少没发齐”，再检查问题。默认显示“需要检查”，按“谁需要检查、哪里不对、接下来怎么做、详情”逐项查看。也可以打开收款名单、付款记录和报告。

### 界面阅读方式

- 页面右上角可切换中文与 English，详情窗口也有切换入口。语言偏好保存在当前浏览器；切换时保留规则、文件、结果、筛选、已展开的来源与所选案例，不会重新计算金额。上传内容、文件名、地址及编号保持原值；系统文案、示例名称与日期说明随语言切换。
- 已发金额只统计付款表中已确认的记录，其中不知道付给谁的钱会说明。一个人多收的钱不能替另一个人算已收到；没发齐的钱中可能有付款还在确认，不能直接照数补发。
- 问题按“金额不对、收款人不明、等待或失败、重复记录”分类。付款还在确认时先查有没有成功；表格重复记录不代表钱发了两次。
- “查看详情”分为“哪里需要注意、接下来怎么做、去哪里查”。完整地址、交易编号、系统检查原文和文件校验码按需展开，所有金额保留完整有效精度。
- 手机端将明细显示为带字段名的信息卡；搜索、筛选、翻页、查看详情和报告下载均可使用。支持键盘操作、可见焦点与 Escape 关闭详情。

更改规则或文件后，旧结果会失效，需要重新核对。所有金额以字符串返回，JavaScript 不重新进行金额运算。示例及输入的付款状态是提交数据的声明，不是现场查询到的链上状态。

网站默认打开产品介绍，顶部导航依次为“项目介绍”“收益核对”。也可直接打开 [介绍页](http://127.0.0.1:8000/#/project/overview) 或 [核对工具](http://127.0.0.1:8000/#/tool)。介绍页以软件产品网站的方式连续展示用途、核对预览、原始依据、目标使用者和项目说明。

- 支持连续滚动与段落直达，保留原有七段链接。桌面用轻薄固定导航定位；手机按阅读顺序展开，键盘方向键保留浏览器原生操作。
- 首屏可选择 B、C、D 查看差额；“查看对应依据”跳到同一人的规则、名单行号和付款行号。100人样本继续展示问题分布，未知收款人单独处理。
- 实际工具中 B 的截图随语言切换；两张场景插画说明工作与交接。所有示例数字来自当前程序，图片不代表真实客户或业务凭证。见 [图片说明](docs/VISUAL_ASSETS.md)。

- 介绍与工具之间切换会保留当前输入、结果和明细筛选，介绍页也保留阅读位置与所选案例。刷新整个网页后仍需重新上传。
- “打印 / 存为 PDF”打印完整介绍及展开的项目依据，打印后恢复原有展开状态。
- 设计依据和布局说明见 [产品介绍页设计](docs/PRODUCT_DESIGN.md)：参考 ADDX 公开产品网站与 Apple 官网的展示方法。

## 核对口径

- 每人应付 = 记录日持有量 × 本期每枚分配额，按六位小数 HALF_UP 舍入；汇总保留舍入调整的完整精度，避免把小于最小付款单位的调整再次舍入。
- 仅将固定核对时点前已确认的有效付款计入实付，待确认、失败分别处理。
- 同一网络 + 交易哈希 + 事件序号内容一致，只计一次；内容冲突要求先更正。
- 不同事件的付款可以合法拆分，不能按地址或金额相同自动删除。
- 金额不足与付款进度分开展示：尚未到期不等于逾期；逾期仍待确认也未结清。
- 未知收款钱包单独展示，不静默丢弃；个人不足额与超额分别汇总。
- 输入缺列、错项目/币种/快照、钱包歧义、非法金额等阻止正式核对，并返回文件、行号及原因。

第一版支持单项目、单批次、单网络、模拟USDC六位金额、每人一个登记EVM钱包及固定CSV模板。每份文件上限5MiB、10,000数据行。时间字段必须带时区。金额和数量请使用普通十进制字符串，不使用科学计数法、千分位或浮点特殊值。

## 报告包

`holders.csv`（个人核对）、`anomalies.csv`（异常、原因与建议核实步骤）、`payment_ledger.csv`（付款处理明细）、`summary.json`（摘要及输入指纹）、`rules.json`（规则）。异常详情同样显示建议核实步骤。证据用于复核本次输入，不构成独立审计认证，也不自动发起补付。

## 代码结构

- `frontend/`：界面、API调用、类型、静态模板和演示数据。
- `frontend/src/components/`：分配设置与导入、核对结果、证据详情、报告；`presentation.ts` 负责中文展示与字符串金额格式化。
- `frontend/src/project/`：连续滚动的产品介绍页、交互预览与程序生成的合成证据。
- `frontend/src/i18n.tsx`、`locale.ts`、`translations/`：语言偏好、无损字符串插值、中英文系统文案；核对金额与输入数据不在翻译层计算或修改。
- `backend/app/`：API、数据结构、CSV解析、精确核对及报告生成。
- `frontend/src/browser-runtime/`：Pages 静态网站的 Python Worker、请求适配及取消处理；复用 `backend/app/` 的校验、计算和导出模块。
- `.github/workflows/pages.yml`：`main` 自动检查并发布 Pages；`frontend/scripts/` 准备经过校验的自托管 Python 依赖，并运行跨环境回归。
- `sample-data/`：可编辑的演示输入。
- `docs/API_CONTRACT.md`：前后端字段与接口约定。
- `scripts/generate_examples.py`：生成合成数据。
- `scripts/generate_project_evidence.py`：用核对程序生成介绍页演示结果。
- `backend/tests/`：业务规则、输入边界、真实HTTP接口及报告一致性的回归检查。
- `scripts/check.sh`：运行回归检查、脚本语法检查和前端构建。

## 修改后的检查
