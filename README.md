# AF5640-gorup

**DistributionCheck 收益分配核对平台**。面向 AF5640 小组项目，核对一次代币收益分配中的应付、已确认实付、待确认及差异，并导出可追溯记录。

项目名称按要求保留为 **AF5640-gorup**。界面为中文，前端 React + TypeScript + Vite，后端 Python + FastAPI，金额使用 Decimal。第一版无数据库，当前批次仅保存在浏览器页面会话中；后端按请求独立处理，刷新后重新上传。

![收益分配对账界面](docs/preview.jpg)

## 启动

首次获取源码：

```bash
git clone https://github.com/iamwzzr/AF5640-gorup.git
cd AF5640-gorup
```

当前电脑已配置依赖并构建完成后，在项目目录运行：

```bash
./start.sh
```

打开 **http://127.0.0.1:8000**。Mac 也可双击 `start.command` 启动，在终端按 Ctrl+C 停止。

换电脑或重新安装时，需要 Python 3.12（支持 3.10+）及 Node.js 22.12+ 或 24 LTS，然后执行：

```bash
./setup.sh
./start.sh
```

可通过 `AF5640_PYTHON=/完整路径/python3 ./setup.sh` 指定 Python。依赖锁定于 `frontend/package-lock.json` 和 `backend/requirements.lock.txt`。安装虚拟环境不能跨电脑复制，应在目标电脑重新创建。当前端口被占用时可运行 `AF5640_PORT=8001 ./start.sh`。

开发时运行 `./dev.sh`，前端在5173端口，后端在8000端口，前端通过代理请求后端。修改前端后，用 `npm --prefix frontend run build` 更新正式界面。

## 使用流程

1. **分配设置**：填写项目、分配批次、持仓记录日、每枚分配额、付款截止及核对时间。项目编号、网络和合约收在可展开设置中，导入前需与 CSV 核对。
2. **导入数据**：上传持有人名单和付款记录 CSV，点击“检查输入”。通过后才能开始核对；模板可直接下载，原始数据预览按需展开。
3. **查看结果**：先读核对结论和三个核心金额，默认查看“待核实事项”，按“需要核实谁、发现什么、下一步做什么、依据”逐项检查。可切换所有持有人或付款记录，并在报告页下载 ZIP。

### 界面阅读方式

- 已确认付出包含未匹配的钱包金额；付款缺口逐人累计，不与超付抵销，也不能直接作为补付清单。金额组成与计算口径可以展开。
- 待核实事项可按金额、身份、付款状态、数据重复分类。待确认付款先查最终状态；重复导入不等于重复付款。
- “查看依据”分为“发现了什么、怎么核实、原始记录”。完整交易哈希、钱包、时间和原始行号在详情中展开，所有金额保留完整有效精度。
- 手机端将明细显示为带字段名的信息卡；搜索、筛选、翻页、查看依据和报告下载均可使用。支持键盘操作、可见焦点与 Escape 关闭详情。

更改规则或文件后，旧结果会失效，需要重新核对。所有金额以字符串返回，前端不重新进行金额运算。示例及输入的付款状态是提交数据的声明，不是现场查询到的链上状态。

## 核对口径

- 每人应付 = 记录日持有量 × 本期每枚分配额，按六位小数 HALF_UP 舍入；汇总保留舍入调整的完整精度，避免把小于最小付款单位的调整再次舍入。
- 仅将固定核对时点前已确认的有效付款计入实付，待确认、失败分别处理。
- 同一网络 + 交易哈希 + 事件序号内容一致，只计一次；内容冲突要求先更正。
- 不同事件的付款可以合法拆分，不能按地址或金额相同自动删除。
- 金额不足与付款进度分开展示：尚未到期不等于逾期；逾期仍待确认也未结清。
- 未知收款钱包单独展示，不静默丢弃；个人不足额与超额分别汇总。
- 输入缺列、错项目/币种/快照、钱包歧义、非法金额等阻止正式核对，并返回文件、行号及原因。

第一版支持单项目、单批次、单网络、模拟USDC六位金额、每人一个登记EVM钱包及固定CSV模板。每份文件上限5MiB、10,000数据行。时间字段必须带时区。金额和数量请使用普通十进制字符串，不使用科学计数法、千分位或浮点特殊值。

## 报告包

`holders.csv`（个人核对）、`anomalies.csv`（异常、原因与建议核实步骤）、`payment_ledger.csv`（付款处理明细）、`summary.json`（摘要及输入指纹）、`rules.json`（规则）。异常详情同样显示建议核实步骤。证据用于复核本次输入，不构成独立审计认证，也不自动发起补付。

## 代码结构

- `frontend/`：界面、API调用、类型、静态模板和演示数据。
- `frontend/src/components/`：分配设置与导入、核对结果、证据详情、报告；`presentation.ts` 负责中文展示与字符串金额格式化。
- `backend/app/`：API、数据结构、CSV解析、精确核对及报告生成。
- `sample-data/`：可编辑的演示输入。
- `docs/API_CONTRACT.md`：前后端字段与接口约定。
- `scripts/generate_examples.py`：生成合成数据。
- `backend/tests/`：业务规则、输入边界、真实HTTP接口及报告一致性的回归检查。
- `scripts/check.sh`：运行回归检查、脚本语法检查和前端构建。

## 修改后的检查

```bash
./scripts/check.sh
```

后端测试使用Python标准库和项目运行依赖，前端接口与展示口径测试使用Node内置测试工具，无需额外测试框架。HTTP测试会自行启动和停止独立的本地服务，不占用8000端口。前端生产构建会同时检查TypeScript类型。修改完成后如后端仍在运行，请重启 `./start.sh` 以载入新代码。

本次构建、回归和浏览器主要流程检查记录见[构建状态](docs/build-status.json)；不据此声称已经完成生产级验证或证实节时比例。
