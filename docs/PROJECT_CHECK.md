# 项目检查记录

最近检查日期：2026-10-23。应用及核对算法版本：1.1.0。10月22日完成原有流程检查，10月23日重新运行全部自动回归，并检查通俗文案及相关界面。

本轮覆盖当前本地原型的规则输入、CSV校验、逐人核对、异常追踪、报告导出及浏览器操作，并完成已确认的界面改进。当前为“填写规则 → 上传表格 → 查看结果”三步流程，报告与原始证据从结果页进入。独立“项目介绍”页面用于解释创业方案、演示证据、商业设想与项目依据。

## 已修复问题

| 问题 | 原表现 | 修复结果 |
| --- | --- | --- |
| 舍入调整精度错误 | 调整0.0000005会被再次舍入为0.000001 | 保留舍入调整的完整十进制精度；应付和实付仍按六位小数处理 |
| 极端日期导致服务器错误 | 转换到UTC超出日期范围时抛出异常 | 在输入校验阶段返回具体日期错误 |
| 特殊时区改变核对时点 | 如+08:00:30在规则序列化时变成+08:00 | 拒绝当前格式无法准确保留的秒级时区偏移 |
| 非报告内容被下载成ZIP | HTTP 200网页响应也会触发ZIP下载 | 检查响应类型；错误格式和无法解析的JSON显示可读错误 |
| 明细搜索与显示内容不一致 | “未知钱包”无法被搜索；各页对空格处理不同 | 纳入显示标签，所有页统一去除搜索词首尾空格 |
| 无效快照产生误导警告 | 持有人文件缺列时，将所有收款钱包报告为未知 | 持有人快照校验通过后才进行跨文件钱包匹配 |

同时补充了100人综合演示数据，以及异常详情和`anomalies.csv`中的建议核实步骤。建议需由使用者人工核实，不会自动执行付款。

## 本轮界面改进

10月23日按用户反馈统一改为通俗表达：三步改为“填写规则、上传表格、查看结果”；结果先回答“这次该发多少、表格里已发多少、还有多少没发齐”。默认表格去掉长钱包地址和交易哈希，技术信息保留在展开详情中。详情改为“哪里需要注意、接下来怎么做、去哪里查”，完整后端说明保留为可展开原文。报告按用途介绍文件，文件名和校验码按需查看。演示名称、错误提示和表格预览同步调整。

介绍页在本轮改为连续滚动的产品网站，默认先打开介绍，顶部导航依次为“项目介绍”“收益核对”。参考 ADDX 的产品价值与使用场景表达、Apple 官网的标题层级与产品画面，应用 `apple-design`、`frontend-design` 和 `ui-ux-pro-max`。旧版逐页演示、章节侧栏和方向键翻页已移除。具体设计依据见 `PRODUCT_DESIGN.md`。

介绍页的演示数据由当前核对程序从原始 5 人、100 人样本生成，并有回归检查防止内容与算法脱节。100 格图只代表登记持有人，未知收款人单独显示；待确认付款保留避免再次发放的提醒。

首屏展示可点击的核对窗口，说明该工具如何比较每个人的应收与已确认付款。5人案例从总额比较延续到 B/C/D 的金额、提示与原始行号；100人样本另行标明用于检查覆盖。插画用于使用场景与报告交接，实际工具截图已经按新版导航重新截取；这些均不是真实客户采用的证明。

现有办法比较明确写出 Tokeny 公开资料已有收益发放及报告能力。当前页面介绍已有功能与商业设想，不声称已有客户采用、测量效果或竞争优势。按用户提供的课程要求，访谈、计时比较和采购意愿调查未被列为必做项，因此已删除额外添加的验证计划及相关中英文承诺。参考资料是公开官网、产品说明和校方报道，未作为原始参赛 PPT 展示。

中文 / English 切换覆盖主工具、完整产品介绍、详情、报告预览与系统错误提示。语言偏好独立保存在浏览器，切换不修改输入文件、金额或结果；筛选、已展开来源、所选案例和项目详情保留。工具与介绍往返后，介绍页保留阅读位置。图片用途与内置 image_gen 的完整生成提示见 `VISUAL_ASSETS.md`。

## 当前尚未实现的能力

当前原型按单项目、单批次、单EVM网络、六位小数付款资产和每人一个登记钱包处理。以下能力尚未实现，展示时应按当前范围介绍：

- 链上自动取数与独立交易核验。当前付款状态和持有人登记关系来自上传文件。
- 账户权限、持久化历史和多人复核流程。刷新后需重新上传，已导出的报告可自行保存。
- 税费、分层分配等复杂条款。目前按记录日持有数量乘以每枚分配额计算。
- 自动处理异常或发起补付。不同真实事件不会因钱包和金额相同而自动删除；超额会保留并要求人工核实原因。

这些是后续产品扩展范围。本轮检查确认的是当前本地原型流程，尚未进行真实机构数据接入或生产部署验证，也未验证人工节时比例及客户付费意愿。
